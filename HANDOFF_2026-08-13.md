## Funcionalidad reciente

- Listado de incidencias ordenado por prioridad descendente y, para la misma prioridad, por antiguedad ascendente.
- Alta de incidencias con uno o varios tecnicos. El primer tecnico se crea con el ticket y el resto se anade mediante relaciones `Ticket_User` de tipo tecnico.
- Edicion desde el detalle de una incidencia, disponible con permiso GLPI de actualizacion: titulo, descripcion, prioridad, solicitante y tecnicos asignados. Al guardar, se conservan las relaciones tecnicas existentes que no hayan cambiado, se eliminan las retiradas y se crean las nuevas.
- El detalle muestra todos los tecnicos asignados.
- Creacion de incidencias en `/incidencias/nueva`.
- La pantalla permite indicar titulo, descripcion, prioridad, solicitante y tecnico asignado.
- `POST /api/tickets` crea en GLPI un `Ticket` con `_users_id_requester` y `_users_id_assign`.
- La creacion exige sesion, origen permitido y permiso GLPI `CREATE` sobre tickets.
- Los campos de titulo y descripcion incluyen boton de dictado Web Speech API (`es-ES`). El dictado exige HTTPS.
- La busqueda de solicitante/tecnico usa `search/User` de GLPI con coincidencia por login, nombre y apellido. No consulta Active Directory directamente.
- Correccion final desplegada: se solicita la columna `2` (ID GLPI) mediante `forcedisplay`; antes los resultados se descartaban por carecer de ID. Prueba autenticada contra GLPI: respuesta `200`, 6 resultados para consulta de prueba y primer ID valido `257`.
- Correccion desplegada en el editor movil: `TicketEditor` separa el contenido desplazable de la barra de acciones. El formulario hace scroll interno y `Guardar cambios` queda fijo al pie sin cubrir el textarea ni los selectores de usuario.
- Si un empleado de AD no aparece, debe sincronizarse/importarse en GLPI; la aplicacion solo puede seleccionar usuarios ya existentes en GLPI.

## Operacion remota

- El acceso no interactivo se autoriza mediante una clave ED25519 local dedicada. Usar la clave privada local correspondiente, sin copiarla al proyecto ni al servidor.
- `fjcarrion` tiene una regla de `sudoers` para ejecutar `/usr/bin/docker` sin solicitar contrasena. Mantener la regla limitada a ese binario.

```sh
ssh fjcarrion@10.158.1.3
cd /home/fjcarrion/glpi-incidencias-movil
sudo docker compose ps
sudo docker compose logs --tail=100 app
sudo docker compose build app
sudo docker compose up -d --force-recreate app
curl --fail http://10.158.1.3/api/health/ready
```
